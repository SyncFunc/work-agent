## 2. 后端能力盘点与缺口（已核实）

| 需求 | 后端现状（核实） | 缺口 |
|---|---|---|
| **上下文占用（真实）** | `Decision.usage` 来自模型 API（`_usage_to_dict` 归一化 `prompt/completion/reasoning/cache_hit/cache_miss`）；`loop.run` 跨轮累加 `usage_total`；`BridgeTransport.report_usage` → `MsgType.USAGE{usage, estimated:false}`（无 usage 才降级 `estimated:true`）。`prompt_tokens` 即真实上下文输入大小（含 system+history+tools）。 | **无需新增消息**。前端用 `latest usage.prompt_tokens / settings.context.window` 算占用% |
| 停止生成 | 无取消机制；`session.step` 跑完；`_run` 经 `asyncio.ensure_future` 但未持有 task | **需改（已定：真实取消）**：持有 `handle.running_task` + 新增 `TASK_CANCEL` + `loop`/Model 可中断 LLM 流 |
| plan/exec 切换 | `/plan` 进、`/exec` 回、`/approve` 批准、`/mode` 查看；`session.plan_mode` 布尔 | 状态同步弱（仅 `useObs` 靠事件推导）。建议新增 `SESSION_INFO{plan_mode, model}` 切换后推送 |
| 模型切换 | `session.model` 构建时固定，无运行时切换 | 本轮定死仅展示；预留 `MODEL_SWITCH` |
| 命令/skill 候选 | `/skills`→`show_skills(list_skills())`；`/agents`→`show_agents`；命令清单在 `useCommands` | 前端拼：命令静态 + skill 经 `show_skills` 缓存一次 |
| 会话删除 | 仅 list/new/attach/switch；**无删除** | **需改**：新增 `SESSION_DELETE` + `SessionStore.delete_session`（范围见 §7-Q3） |
| 响应 token/耗时 | `MsgType.USAGE` 每 step 结束推真实 `usage`；未与某响应分组绑定 | 前端按「助手 turn」聚合 `usage` + 时间戳算耗时，**无需后端改** |
| 设置完整项 | `settings.py` 含 llm/context/resilience/obs/daemon/plan/skills/approval | 前端 `settingsApi` 仅 3 字段，需扩展 schema |

## 3. 功能设计

### 3.1 输入框底栏（Composer footer）
圆角独立容器（参考图）：上方一行扩展按钮（附件 + 其他），下方工具栏：
- **上下文占用 Badge**：`上下文 NN%`（`prompt_tokens / context.window`）。hover 弹出明细卡片：
  - `prompt_tokens`（输入/上下文占用）
  - `completion_tokens`、`reasoning_tokens`
  - `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`
  - `total_tokens`
  - 进度条（>=93% 红色预警，阈值对齐 `ContextManager._COMPACT_TRIGGER_PCT`）
  - 数据源：`MsgType.USAGE`（真实，`estimated:false`）+ 前端读 `settings.context.window`
- **停止生成**：仅 `handle.running` 时显示；点击发 `TASK_CANCEL`，后端**真实取消**当前 step（持有 `handle.running_task` 并中断 LLM 流，见 §5-①）
- **模式切换**：分段控件 `PLAN | EXEC`（参考图 "Craft" 形态），点击发 `/plan`、`/exec`；状态来自 `SESSION_INFO.plan_mode`（回退 `useObs.mode`）
- **模型切换**：只读标签（如 `deepseek-v4-flash`），定死；预留下拉骨架
- **Skills 按钮**：点开 skill 候选/面板（见 §3.2/§3.3）
- **附件 / 发送**：附件在左上；发送按钮在底栏最右（图标按钮）

### 3.2 命令 / skill 候选框
- 触发：输入框以 `/` 开头（光标在行首/`/` 后）时，`Composer` 上方浮出 `CommandCandidateList`
- 数据：命令=`useCommands` 静态清单；skill=挂载时发一次 `/skills` 缓存 `show_skills`；可加 agents 分组
- 交互：↑↓ 选、Enter 填充 `/name `（skill 填 `/skill_name ` 并聚焦参数）、Esc 关；复用 `parseSlash`
- 与 `CommandPalette`（⌘K 全局）并存

### 3.3 部分命令交互式发起
`useCommands` 每条增 `interactive?: 'confirm'|'picker'|'panel'` 字段：
- `/clear`：二次确认弹窗
- `/new`：直接新建（跳确认）
- `/plan`·`/exec`·`/approve`：由 §3.1 切换控件覆盖
- `/model`：模型选择器（本轮仅展示）
- `/skills`·`/agents`：打开 Skills/Agents 浏览面板（列表+描述+加载）
- `/init`：向导式（后续）

### 3.4 会话历史删除
- 交互：会话项 hover 出删除图标 → 确认 → 发 `SESSION_DELETE{session_id}`
- 后端：新增 `SESSION_DELETE{session_id}` 消息 + `SessionStore.delete_session` **彻底删除**（会话记录 + 事件流 + 关联 Session Memory + trace 一并清理，见 §7-Q6）
- 删除后前端移除；若删当前会话则自动切换/新建

### 3.5 AI 响应底部工具条（每条助手消息）
`MessageItem` 底栏（`role==='assistant'`）：
- 左：复制 / 点赞 / 点踩 / 更多（更多含「查看 trace」等）
- 右：胶囊信息条 `Token 消耗` + `耗时`（**省略「积分」**——我们无 credits 系统，见 §7-Q4）
- **Token 明细 hover**：聚合该 turn 的 `usage` → 展示 `prompt/completion/reasoning/cache_hit/cache_miss/total`
- **耗时**：该 turn 首个内容事件 → 收到 `usage`/`FINAL` 时间差（前端计时）
- 多 step turn：累加多个 `usage` 事件

### 3.6 设置面板升级
- 打开：点击设置 → 聊天主区**整屏替换** `SettingsPanel`，顶部「← 返回」（非弹窗/抽屉）
- 补全字段（据 `settings.py`）：`llm`(api_key/base_url/model/temperature/max_tokens/timeout/max_retries/reasoning_effort)、`context`(window/buffer/event_stream_maxlen/compaction/*_enabled)、`resilience`(rate_limit/circuit_breaker/backoff)、`obs`(enabled/db_path/sessions_db_path)、`daemon`(host/port/health_port/token)、`plan`/`approval`/`skills`
- 分组折叠 + 校验（端口/数字）+ 敏感字段掩码 → `patch` → `saveSettings` 写回 `settings.yaml`

## 4. 布局设计（CodeBuddy 风格）

整体：**顶部标题栏（全宽，较窄）+ 左侧固定导航栏 + 右侧主区（聊天，可叠加可切换的可观测侧栏）**。

### 4.1 自绘顶部标题栏 `TitleBar`（替代 Electron 系统栏）
- `main/index.ts`：`BrowserWindow` 设 `frame: false`（Windows 自绘窗口控制）
- 左上：CSS 绘制的 **Logo** + 应用名（自有产品名，常量可配，默认 `WorkAgent`，见 §7-Q1）；其后**真实功能菜单** `文件 / 编辑 / 窗口 / 帮助`：`文件→打开文件夹（切换工作区 project_root）`、`窗口→关闭窗口/重新加载`、`帮助→占位`
- 中间：当前页面名（如 `聊天` / `技能` / `智能体` / `可观测`）
- 右上：应用头像 / 编辑器入口 / 设置按钮 / 菜单按钮 / **侧栏切换按钮**（切换右侧 ObsPanel）/ 最小·最大·关闭（SVG，经 IPC）
- 配色走全局 CSS 变量，与主题一致

### 4.2 左侧导航栏 `Sidebar`（上下分区，固定宽）
- 顶部：`Logo` + 版本号；下方**横向搜索框**（搜任务/历史）；其下**「新建任务」按钮**（近满宽，主操作入口）
- 导航菜单（纵向，图标+文字）：`技能`(Skills) / `智能体`(Agents) / `可观测`(Traces)；`聊天` 为默认主视图（不在菜单内切换）
- 「工作空间」标题 + 当前项目 **basename**（如 `work-agent`）
- 会话历史列表：每行 = 文档图标 + 标题（过长截断）+ 相对时间（`19分钟前`/`3小时前`/`1天前`）+ 未处理标记；底部「展开更多（N）」
- 最底部：用户信息栏（头像 + 用户名 + 展开箭头）

### 4.3 右侧主区 `MainArea`
- 会话标题栏（顶，贴内容）：返回按钮 + 状态图标 + 当前任务标题（长文本截断）
- 聊天内容区：消息卡片；助手回复含 头像+名称+「深度思考」状态；用户消息右侧气泡；大左右边距；接近底部有滚动定位按钮
- 输入区：独立圆角容器（见 §3.1）
- 可观测面板（`ObsPanel`）作为**可切换右栏**，由标题栏「侧栏切换」控制显隐

## 5. 实现步骤拆解（建议顺序）

1. **后端（本次需改）**：`TASK_CANCEL` + 持有 `handle.running_task` + `loop`/Model 可中断 LLM 流（真实取消）；`SESSION_DELETE` + store **彻底删除**（会话+事件+Session Memory+trace）；`SESSION_INFO{plan_mode,model}` 推送。→ 上下文占用**无需后端改**。
2. **顶栏 + frameless**：`TitleBar` + IPC 窗口控制；`frame:false`。
3. **左侧栏重排**：Logo/搜索/新建任务/导航菜单/工作空间+历史/用户栏。
4. **Composer 改造**：圆角容器 + 底栏（上下文占用/停止/模式/模型/Skills/附件/发送）。
5. **候选框 + 交互命令**：`CommandCandidateList` + `useCommands.interactive`。
6. **会话删除**：UI + 后端联调。
7. **响应工具条**：复制/点赞/点踩/更多 + Token/耗时 + 明细（前端聚合真实 `usage`）。
8. **设置面板升级**：整屏打开 + 全字段 schema。
9. **联调 + 视觉对齐参考图**。
