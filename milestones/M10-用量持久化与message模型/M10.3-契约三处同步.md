# Step M10.3 契约三处同步（删除 MsgType.USAGE）

## 实现方案

- 目标：usage 由「`MsgType.USAGE` 实时消息」改为「`event` 消息内的 `USAGE` 子类型」，使三处契约（事实来源 / 前端投影 / 一致性测试）保持一致。**这是改双端契约，必须先冻结协议再改前端**（`CODEBUDDY.MD` §7.1）。

- 改动文件（强制同步三处 + 文档）：
  - `agent/daemon/protocol.py`（**MsgType 唯一事实来源**）
  - `desktop/src/protocol/types.ts`（**前端强类型投影**）
  - `scripts/check-msgtype.mjs`（**一致性测试**）
  - `docs/daemon-api.md`（**接口文档**）
  - `agent/daemon/client.py`（移除 `MsgType.USAGE` 分支）
  - `agent/tui/app.py`（移除 `transport.report_usage(res.usage, ...)`，改向 session stream append `USAGE` 事件）

- 关键接口 / 算法：

  **1. `protocol.py` 删除 `USAGE`（`MsgType`）**
  - 删除 `USAGE = "usage"`（当前 `protocol.py:87`）。
  - 更新模块 docstring 的「方向约定」Server → Client 列表，移除 `/usage`；并补一句：usage 现以 `event` 消息内的 `USAGE` 事件子类型承载，payload 含 `message_id` / `parent_message_id` / `usage` / `duration` / `estimated`。
  - `make_message` / `parse_message` 无需改（`type` 仍为字符串）；`USAGE` 事件走既有 `EVENT` 消息信封。

  **2. `types.ts` 删除 `'usage'` 并修正类型**
  - `ALL_MSG_TYPES` 移除 `'usage'`（当前 `types.ts:39`）。
  - `EventTypeStr` 增加 `'usage'`（当前为 `'user'` 收尾）。
  - `AgentEvent` 增加 `message_id?: string | null` 与 `parent_message_id?: string | null`。
  - 将 `UsagePayload`（当前用于 `report_usage` 投影）改为 `UsageEvent` 投影，描述 `USAGE` 事件字段：
    ```ts
    export interface UsageEvent {
      message_id: string
      parent_message_id?: string | null
      usage: {
        prompt_tokens?: number
        completion_tokens?: number
        total_tokens?: number
        reasoning_tokens?: number
        cache_hit_tokens?: number
        cache_miss_tokens?: number
        cache_write_tokens?: number
        estimated_tokens?: number
      }
      duration: number      // 秒，墙钟
      estimated: boolean
    }
    ```
    （旧 `UsagePayload` 中的 `usage` 形状直接复用。）

  **3. `scripts/check-msgtype.mjs`**
  - 该脚本比对 Python 端 `MsgType` 枚举与 `types.ts` 的 `ALL_MSG_TYPES`；删掉 `USAGE` 后两侧一致即通过。无需改动逻辑（除非它单独白名单了 `usage`，则一并移除）。

  **4. `docs/daemon-api.md`**
  - 更新「用量/耗时」小节：usage 现为 `event` 消息内的 `USAGE` 事件（非独立 `MsgType`）。
  - 新增字段说明：`message_id` / `parent_message_id` / `usage` / `duration` / `estimated`。
  - 更新回放小节：回放逐条发 `event`，自然包含 `USAGE` 事件，重启后可恢复历史用量。
  - 标注 `parent_session_id`（子会话↔父会话）已具备并透传，本次 message 层新增 `parent_message_id`（message↔message）。

- 依赖 / 环境：依赖 M10.2 已使 live 路径产出 `USAGE` 事件；本步删 `MsgType.USAGE` 后，前后端均只走 `event`/`USAGE` 子类型。
