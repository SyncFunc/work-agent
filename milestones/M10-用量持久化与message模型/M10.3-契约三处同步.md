# Step M10.3 契约三处同步（删除 MsgType.USAGE）

## 实现方案

- 目标：usage 由「`MsgType.USAGE` 实时消息」改为「`event` 消息内的 `USAGE` 子类型」，使三处契约（事实来源 / 前端投影 / 一致性测试）保持一致。**这是改双端契约，必须先冻结协议再改前端**（`CODEBUDDY.MD` §7.1）。

- 改动文件（强制同步三处 + 文档）：
  - `agent/daemon/protocol.py`（**MsgType 唯一事实来源**）
  - `desktop/src/protocol/types.ts`（**前端强类型投影**）
  - `scripts/check-msgtype.mjs`（**一致性测试**）
  - `docs/daemon-api.md`（**接口文档**）
  - `agent/daemon/client.py`（移除 `MsgType.USAGE` 分支）
  - `agent/tui/app.py`（移除 `transport.report_usage(res.usage, ...)`，改向 session stream append `USAGE` 事件）

- 关键接口 / 算法：

  **1. `protocol.py` 删除 `USAGE`（`MsgType`）**
  - 删除 `USAGE = "usage"`（当前 `protocol.py:87`）。
  - 更新模块 docstring 的「方向约定」Server → Client 列表，移除 `/usage`；并补一句：usage 现以 `event` 消息内的 `USAGE` 事件子类型承载，payload 含 `message_id` / `parent_message_id` / `usage` / `duration` / `estimated`。
  - `make_message` / `parse_message` 无需改（`type` 仍为字符串）；`USAGE` 事件走既有 `EVENT` 消息信封。

  **2. `types.ts` 删除 `'usage'` 并修正类型**
  - `ALL_MSG_TYPES` 移除 `'usage'`（当前 `types.ts:39`）。
  - `EventTypeStr` 增加 `'usage'`（当前为 `'user'` 收尾）。
  - `AgentEvent` 增加 `message_id?: string | null` 与 `parent_message_id?: string | null`。
  - 将 `UsagePayload`（当前用于 `report_usage` 投影）改为 `UsageEvent` 投影，描述 `USAGE` 事件字段：
    ```ts
    export interface UsageEvent {
      message_id: string
      parent_message_id?: string | null
      usage: {
        prompt_tokens?: number
        completion_tokens?: number
        total_tokens?: number
        reasoning_tokens?: number
        cache_hit_tokens?: number
        cache_miss_tokens?: number
        cache_write_tokens?: number
        estimated_tokens?: number
      }
      duration: number      // 秒，墙钟
      estimated: boolean
    }
    ```
    （旧 `UsagePayload` 中的 `usage` 形状直接复用。）

  **3. `scripts/check-msgtype.mjs`**
  - 该脚本比对 Python 端 `MsgType` 枚举与 `types.ts` 的 `ALL_MSG_TYPES`；删掉 `USAGE` 后两侧一致即通过。无需改动逻辑（除非它单独白名单了 `usage`，则一并移除）。

  **4. `docs/daemon-api.md`**
  - 更新「用量/耗时」小节：usage 现为 `event` 消息内的 `USAGE` 事件（非独立 `MsgType`）。
  - 新增字段说明：`message_id` / `parent_message_id` / `usage` / `duration` / `estimated`。
  - 更新回放小节：回放逐条发 `event`，自然包含 `USAGE` 事件，重启后可恢复历史用量。
  - 标注 `parent_session_id`（子会话↔父会话）已具备并透传，本次 message 层新增 `parent_message_id`（message↔message）。

- 依赖 / 环境：依赖 M10.2 已使 live 路径产出 `USAGE` 事件；本步删 `MsgType.USAGE` 后，前后端均只走 `event`/`USAGE` 子类型。

## 知识沉淀

### 与文档方案的实现差异（重要）
- 文档只列了 protocol.py / types.ts / check-msgtype.mjs / docs/daemon-api.md / client.py / app.py 六处，但实际删 `MsgType.USAGE` 后**必须联动更多文件**才能过门禁（否则 pyright/tsc/pytest 挂）：
  - `agent/daemon/bridge.py`：原 `report_usage` 用 `MsgType.USAGE` 发实时消息，删 MsgType 后该引用非法 → 改为保留 `report_usage` **no-op 占位**（满足 `AgentTransport` 抽象协议，不再引用 MsgType.USAGE；daemon 用量已改由 `_emit_usage`/`_emit_subagent_usage` 经 USAGE 事件落盘）。
  - `desktop/src/protocol/events.ts`：`EVENT_TYPES` 必须补 `'usage'`（原无），否则前端 `parseEvent` 收到 USAGE 事件抛 `TypeError: 未知 Event.type`；并在 `parseEvent`/`eventToDict` 同步字段 `usage`/`estimated`/`duration`/`message_id`/`parent_message_id`。
  - `desktop/src/renderer/App.tsx` 与 `desktop/src/features/obs/useObs.ts`：原监听 `client.onMessage('usage', ...)` → 改为 `client.onEvent(ev => ev.type === 'usage')` 读取（消费 `event` 信封内的 USAGE 子类型）；`StatusBar.tsx` 的 `UsagePayload` 重命名引用同步改为 `UsageEvent`。
  - `agent/runtime/terminal_transport.py` 与 `agent/runtime/textual_transport.py`：`_on_event`/`on_event` 新增 `EventType.USAGE` 分支 → 调 `self.report_usage(ev.usage, ev.text)`（CLI/TUI 连接 daemon 时经 EVENT 消息实时显示用量，与 M10.2 删除 live 路径前的 `MsgType.USAGE` 渲染行为等价）。
  - `agent/tui/app.py`：按文档移除 `transport.report_usage(res.usage, res.text)`，改 `self._append_usage_event(session, res)` 向 `session.event_stream` append `USAGE` 事件（TextualTransport 订阅该流后渲染），与 daemon 路径一致。

### 契约 / 类型约定（易忘）
- **改协议必须同步 4 处**：`protocol.py` + `types.ts`(ALL_MSG_TYPES) + `check-msgtype.mjs` + `docs/daemon-api.md`；任一遗漏契约测试即挂。`EventTypeStr`/`EVENT_TYPES` 与 Python `EventType` 也要对齐（独立、本步补 `'usage'`）。
- **USAGE 事件线格式（wire）**：`Event.usage` 仅含 token 字典（prompt_tokens…estimated_tokens）；`estimated`/`duration`/`message_id`/`parent_message_id` 是 **Event 顶层兄弟字段**（非嵌套在 `usage` 内）。前端 `AgentEvent` 因此 `usage` 为内层字典类型（`UsageEvent['usage']`），`estimated`/`duration` 为顶层可选字段——`App.tsx`/`useObs.ts` 必须用 `ev.estimated`/`ev.duration`/`ev.usage`(字典)，**不能**用 `ev.usage.estimated`。
- `UsageEvent` 接口 = 原 `UsagePayload` 重命名，描述 USAGE 事件投影（含 usage 字典 + estimated + duration + message_id + parent_message_id）。

### 踩坑
- `AgentTransport.report_usage` 是抽象协议方法；从 `BridgeTransport` 彻底删除会触发 pyright「抽象类不可实例化」（server.py 实例化 BridgeTransport）。必须保留一个 no-op 实现（参数名须与基类一致 `usage`/`answer`，用 `_ = (usage, answer)` 规避 ruff ARG002）。
- `MsgType` 计数契约测试（`test_m9_protocol_contract.py` 断言 `== 37`）删 `USAGE` 后须改为 `== 36`；`tests/unit/test_protocol.py` 的 `values` 列表也要移除 `"usage"`，否则两处 pytest 失败。
