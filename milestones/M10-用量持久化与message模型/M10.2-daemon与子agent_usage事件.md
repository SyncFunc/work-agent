# Step M10.2 daemon 与子 agent 的 USAGE 事件

## 实现方案

- 目标：在每轮（顶层 `task.send` + 每个子 agent 调用）结束时，把 `{message_id, parent_message_id, usage, duration, estimated}` 作为一条 `USAGE` 事件 `append` 进对应 `EventStream`（`SessionStoreSink` 自动落盘、`_on_event` 经 `event` 消息实时转发、`_replay` 自然带出）。**替换**原 `transport.report_usage()` 的 `MsgType.USAGE` 实时消息路径。

- 改动文件：
  - `agent/daemon/server.py`（`_task_send`）
  - `agent/daemon/bridge.py`（`SubsessionBridgeTransport`）
  - `agent/subagent.py`（`SubagentSpawner.spawn`）
  - `agent/tui/app.py`（TUI 路径同步：改向 session stream append USAGE 事件，移除 `transport.report_usage`）
  - `agent/runtime/textual_transport.py` / `agent/runtime/terminal_transport.py`（`report_usage` 保留供 CLI 打印；`_on_event` 新增对 `USAGE` 事件的打印，主路径统一走事件，避免双份）

- 关键接口 / 算法：

  **1. `server.py` 的 `_task_send`（顶层 message）**
  ```python
  async def _task_send(self, handle, text, yes, plan):
      message_id = uuid4().hex
      t0 = time.time()
      # 通过 session.step 设置 stream.current_message_id（见 M10.1）
      res = await handle.session.step(text, message_id=message_id, parent_message_id=None)
      duration = time.time() - t0
      usage_ev = Event(
          type=EventType.USAGE,
          message_id=message_id,
          parent_message_id=None,
          # usage / duration / estimated 装入 data 字段（复用既有 data 承载方式）
          decision=None,  # 不占用 decision；用独立承载
          ...
      )
      handle.stream.append(usage_ev)   # 替换 transport.report_usage(res.usage, ...)
  ```
  > `usage` / `duration` / `estimated` 的承载：建议在 `Event` 新增可选字段 `usage: dict | None`、`duration: float | None`、`estimated: bool = False`（在 M10.1 的 `events.py` 一并加，或本步补），由 `to_dict` / `from_dict` 同步。

  **2. `subagent.py` 的 `SubagentSpawner.spawn`（子 message）**
  ```python
  def spawn(self, *, parent_message_id, task, ...):
      sub_message_id = uuid4().hex
      t0 = time.time()
      # 子会话的 event_stream 设置 current_message_id
      res = sub_session.step(task, message_id=sub_message_id, parent_message_id=parent_message_id)
      duration = time.time() - t0
      sub_stream.append(Event(
          type=EventType.USAGE,
          message_id=sub_message_id,
          parent_message_id=parent_message_id,   # 指向派生子 agent 的那条 message
          ...
      ))
  ```

  **3. `bridge.py` 的 `SubsessionBridgeTransport`**
  - 子事件已带 `subsession_id`；在 spawn 处把顶层 `parent_message_id` 透传给 `SubagentSpawner.spawn`。
  - 因 live 用量改由 `_on_event` 收到的 `USAGE` 事件驱动，可删除 `report_usage` 方法（或保留为空操作以兼容 TUI）。

- 依赖 / 环境：依赖 M10.1 已落地（`message_id` 漏斗、`EventType.USAGE`、`AgentResult.message_id`）。

## 知识沉淀

### 与文档方案的实现差异（重要）
- 顶层 `message_id` **不**在 `_task_send` 内单独生成：复用 `session.step` 内部生成的 `mid`（经 `AgentResult.message_id` 回传），`_emit_usage` 取 `res.message_id`（兜底 `stream.current_message_id`）。比文档伪代码少一处 message_id 来源，避免与 `session.step` 重复生成导致不一致。
- **本步未改 TUI / CLI 的 `app.py` / `textual_transport.py` / `terminal_transport.py`**：daemon 是唯一 live 用量路径，切换为 USAGE 事件即满足验收且零回归风险；TUI/CLI 的 `report_usage` 保留（M10.3 删 `MsgType.USAGE` 时一并切换）。文档原方案列了这几处，实际延后处理更安全。

### 关键接口 / 约定
- `EventType.USAGE` 事件（`agent/core/events.py`，M10.1 加 `usage/duration/estimated`）：**`transient` 默认 `False`** → 自动进 `handle.event_buffer`（回放可读）+ 经 `SessionStoreSink` 落盘 + `_on_event` 转 `EVENT` 消息（payload 含 `event.type=="usage"`）。
- 顶层：`server.py._emit_usage(stream, res, duration, *, parent_message_id)` 为用量落盘入口；`usage` 为空时退化为 `_estimate_tokens(res.text)` 估算并标 `estimated=True`（与旧 `report_usage` 行为一致）。
- 子 agent：`SubagentSpawner.spawn(..., parent_message_id: str|None=None)` 新增参数；daemon 分支（parent_handle+registry 注入）在 `loop.run` 返回后调 `self._emit_subagent_usage(sub_stream, result, duration, parent_message_id=parent_message_id)`；`sub_message_id` 由 spawn 生成并传给 `loop.run(message_id=sub_message_id)`，子事件 `parent_message_id` 指向父 message，形成 message 树。
- `loop._tool_spawn_subagent`：把当前 run 的 message_id 透传为 `parent_message_id=self._run_message_id`（loop.run 入口 `self._run_message_id = message_id`）。

### 踩坑（易忘）
- **`_run_message_id` 必须在 `AgentLoop.__init__` 显式初始化为 `None`**：`run()` 内赋值仅在真正跑 `run` 时生效；单测常直接调 `loop._tool_spawn_subagent`（绕过 `run`），若无 `__init__` 初始化会 `AttributeError: 'AgentLoop' object has no attribute '_run_message_id'`。
- **`_emit_subagent_usage(self, stream, result, duration, *, parent_message_id)` 的 `parent_message_id` 是 keyword-only**：调用处必须 `parent_message_id=parent_message_id` 关键字传参；位置传参会 `TypeError: takes 3 positional arguments but 4 were given`（`self` 绑定后只剩 3 个位置形参）。
- **同文件多 `replace_in_file` 并行可能只部分生效**：实测一条消息对 `subagent.py` 发多个 edit 时，`import uuid as _uuid` 上移与 `sub_message_id` 初始化等改动未落地（其它 edit 成功），导致 `NameError: sub_message_id`。结论：同文件多 edit 必须串行或改完即跑 `ruff --fix`+测试兜底。
- 子会话事件带 `parent_session_id=parent_handle.session_id` 落盘；`_replay` 的 `iter_events_with_subsession(sid)` 会把父子事件一并回放，前端按 `subsession_id` 分桶。
