# Step M10.4 前端按 message 聚合渲染

## 实现方案

- 目标：前端从「全会话单一内存 `turnMeta`」切换为「按 `message` 挂载的 `turnMeta`」，并应用**子 agent 归集规则**——子 agent 的 `usage` + `duration` 向上归集到根 message（顶层 `ResponseBlock`），子 agent 块不渲染消耗信息。实时与回放走同一条 reducer 路径，重启后可恢复。

- 改动文件：
  - `desktop/src/protocol/types.ts`（`AgentEvent` 加 `message_id` / `parent_message_id`；`EventTypeStr` 加 `'usage'`；`UsagePayload` → `UsageEvent`）
  - `desktop/src/features/chat/useEventReducer.ts`（透传 message 字段 + 新增 `usage` 事件处理 + 归集映射）
  - `desktop/src/renderer/App.tsx`（移除内存版 `turnMeta` / `turnUsageRef` / `turnStartRef` / `estimatedRef` 与 `onMessage('usage')`；可选保留进行中 message 的轻量实时耗时 tick）
  - `desktop/src/features/obs/useObs.ts` + `StatusBar.tsx`（由 `usage` 事件累积会话级 usage，回放即恢复）
  - `desktop/src/features/chat/ResponseToolbar.tsx`（读 `block.turnMeta`，每轮独立明细）
  - `desktop/src/features/chat/MessageList.tsx` / `MessageItem.tsx`（`turnMeta` 从「全会话 prop」改为「每块自带 `turnMeta`」）
  - `desktop/src/features/chat/SubagentBlock` 组件（**不渲染** `turnMeta`）

- 关键接口 / 算法：

  **1. `useEventReducer.ts` 的 `usage` 事件处理（核心）**
  ```ts
  // 维护 messageId -> rootMessageId 映射（子 agent 的 root = 其父的 root）
  const rootOf = (m: string, parent?: string | null): string => {
    if (!parent) return m            // 顶层 message 即根
    rootMap.set(m, parent)           // 直接父；查询时再向上追溯
    return findRoot(parent)
  }
  // USAGE 事件一律累加到 root 顶层 ResponseBlock 的 turnMeta
  case 'usage': {
    const root = resolveRoot(ev.message_id, ev.parent_message_id)
    const block = blocksByMessageId[root]   // 顶层 ResponseBlock
    block.turnMeta = block.turnMeta ?? { prompt_tokens: 0, completion_tokens: 0, total_tokens: 0, duration: 0, estimated: ev.estimated }
    block.turnMeta.total_tokens  += ev.usage.total_tokens  ?? 0
    block.turnMeta.prompt_tokens += ev.usage.prompt_tokens ?? 0
    // ... 其余 token 字段累加；duration 累加
    block.turnMeta.duration += ev.duration
    // 子 agent 块（parent_message_id 非空）不挂 turnMeta
    break
  }
  ```
  - 嵌套子 agent：`resolveRoot` 沿 `rootMap` 向上追溯至根，自然归集到同一根 message。
  - 顶层 message（`parent_message_id` 空）：`turnMeta` 直接挂到该 message 对应的顶层 `ResponseBlock`。

  **2. `App.tsx` 清理**
  - 删除 `useState` 的内存版 `turnMeta` / `turnUsageRef` / `turnStartRef` / `estimatedRef`。
  - 删除 `onMessage('usage', ...)` 监听。
  - 可选：保留「当前进行中 message」的轻量实时耗时 tick（仅展示进行中，不持久化、不进入 reducer）。

  **3. `useObs.ts` + `StatusBar.tsx`**
  - 会话级 usage 改为由 `usage` 事件累积（`turnMeta` 合计后的数值或逐事件累加），回放即恢复，不再依赖内存。

  **4. `ResponseToolbar.tsx`**
  - 读取 `block.turnMeta`（每轮独立明细），展示「tokens / 耗时」。

  **5. `SubagentBlock`**
  - **不渲染** `turnMeta`（任何 token / 耗时信息都不出现在子 agent 卡片底部）。

- 依赖 / 环境：依赖 M10.3 已删除 `MsgType.USAGE` 并完成类型投影；本步只消费 `event` 内的 `USAGE` 事件。

## 验收标准

- [ ] 前端门禁：`npm run typecheck`（`tsc --noEmit`）全绿；`npm run test`（`vitest run`）全绿；`npm run build`（`electron-vite build`）全绿。
- [ ] 行为：启动 daemon → 发任务（含触发子 agent）→ 顶层 `ResponseBlock` 底部显示「自身 + 全部子孙子 agent」累计的 tokens / 耗时；子 agent 块底部不渲染消耗。
- [ ] 行为：**重启桌面端** → 历史消息的用量/耗时仍在（由回放的 `USAGE` 事件重建）；子 agent 响应可追溯到父 message。
- [ ] 不变量：`App.tsx` 无内存版 `turnMeta`；用量展示仅来自 reducer 的 `block.turnMeta`，实时与回放路径一致。

>
> 要点提示：
> - 子 agent 消耗向上归集的前提：后端必须为每个子 agent emit 自己的 `USAGE` 事件（带 `parent_message_id`），否则前端无从归集。
> - 子 agent 块「不渲染」是前端硬规则，由 reducer 对 `parent_message_id` 非空事件不挂 `turnMeta` 保证。
> - 会话级 usage 统一由 `usage` 事件累积，告别易失的 React 内存。
